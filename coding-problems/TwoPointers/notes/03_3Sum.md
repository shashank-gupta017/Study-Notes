# 3Sum (Medium)

## Problem Statement
Given an integer array `nums`, return all the **triplets** `[nums[i], nums[j], nums[k]]` such that `i != j`, `i != k`, and `j != k`, and `nums[i] + nums[j] + nums[k] == 0`.

Notice that the solution set must **not contain duplicate triplets**.

**LeetCode Link**: [15. 3Sum](https://leetcode.com/problems/3sum/)

---

## Examples

### Example 1:
```
Input: nums = [-1,0,1,2,-1,-4]
Output: [[-1,-1,2],[-1,0,1]]
Explanation: 
nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0
nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0
nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0
The distinct triplets are [-1,0,1] and [-1,-1,2].
Notice that the order of the output and the order of the triplets does not matter.
```

### Example 2:
```
Input: nums = [0,1,1]
Output: []
Explanation: The only possible triplet does not sum up to 0.
```

### Example 3:
```
Input: nums = [0,0,0]
Output: [[0,0,0]]
Explanation: The only possible triplet sums up to 0.
```

## Constraints
- `3 <= nums.length <= 3000`
- `-10^5 <= nums[i] <= 10^5`

## Pattern Recognition

This is a **Two Pointers + Loop (Nested)** problem because:
1. We need to find **three numbers** (triplet) that satisfy a condition
2. We can **sort** the array and use **two pointers** for inner search
3. We need to **avoid duplicate triplets** (requires careful handling)
4. Brute force O(n³) can be optimized to O(n²)

**Key Insight**: 3Sum = Fixed element + Two Sum II on remaining array!
- Fix first number with outer loop
- Use two pointers on remaining sorted portion to find pair
- Skip duplicates at all three positions

## Approaches

### Approach 1: Brute Force (NOT RECOMMENDED)
**Idea**: Try all possible triplet combinations.

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        Set<List<Integer>> result = new HashSet<>();
        
        // Try all combinations
        for (int i = 0; i < nums.length - 2; i++) {
            for (int j = i + 1; j < nums.length - 1; j++) {
                for (int k = j + 1; k < nums.length; k++) {
                    if (nums[i] + nums[j] + nums[k] == 0) {
                        List<Integer> triplet = Arrays.asList(nums[i], nums[j], nums[k]);
                        Collections.sort(triplet);
                        result.add(triplet);
                    }
                }
            }
        }
        
        return new ArrayList<>(result);
    }
}
```

**Time Complexity**: O(n³) - three nested loops
**Space Complexity**: O(n) - for result storage
**Problem**: Too slow! Will time out on large inputs.

---

### Approach 2: Sort + Two Pointers (OPTIMAL) ⭐
**Idea**: Sort array, fix one element, use two pointers to find remaining pair.

```java
import java.util.*;

class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        
        // Sort the array first
        Arrays.sort(nums);
        
        // Fix first element with outer loop
        for (int i = 0; i < nums.length - 2; i++) {
            // Skip duplicates for first element
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }
            
            // Use two pointers for remaining array
            int left = i + 1;
            int right = nums.length - 1;
            int target = -nums[i]; // We need nums[left] + nums[right] = -nums[i]
            
            while (left < right) {
                int sum = nums[left] + nums[right];
                
                if (sum == target) {
                    // Found a triplet!
                    result.add(Arrays.asList(nums[i], nums[left], nums[right]));
                    
                    // Skip duplicates for left pointer
                    while (left < right && nums[left] == nums[left + 1]) {
                        left++;
                    }
                    
                    // Skip duplicates for right pointer
                    while (left < right && nums[right] == nums[right - 1]) {
                        right--;
                    }
                    
                    // Move both pointers
                    left++;
                    right--;
                    
                } else if (sum < target) {
                    left++; // Need larger sum
                } else {
                    right--; // Need smaller sum
                }
            }
        }
        
        return result;
    }
}
```

**Time Complexity**: O(n²) - O(n log n) for sort + O(n) × O(n) for nested loops
**Space Complexity**: O(1) - ignoring output, only use pointers
**Why Optimal**: Best possible time complexity for this problem

### Approach 3: HashMap (Alternative)
**Idea**: For each pair, check if complement exists in map.

```java
import java.util.*;

class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        Set<List<Integer>> result = new HashSet<>();
        Arrays.sort(nums); // Still need to sort for duplicate handling
        
        for (int i = 0; i < nums.length - 2; i++) {
            Set<Integer> seen = new HashSet<>();
            
            for (int j = i + 1; j < nums.length; j++) {
                int complement = -(nums[i] + nums[j]);
                
                if (seen.contains(complement)) {
                    List<Integer> triplet = Arrays.asList(nums[i], complement, nums[j]);
                    result.add(triplet);
                }
                
                seen.add(nums[j]);
            }
        }
        
        return new ArrayList<>(result);
    }
}
```

**Time Complexity**: O(n²) - same as two pointers
**Space Complexity**: O(n) - HashMap storage
**Note**: Two pointers is cleaner and more space-efficient

## Common Mistakes to Avoid

### Mistake 1: Not Sorting the Array
```java
// ❌ WRONG: Skipping sort
for (int i = 0; i < nums.length; i++) {
    int left = i + 1;
    int right = nums.length - 1;
    // Two pointers won't work on unsorted array!
}

// ✅ CORRECT: Always sort first
Arrays.sort(nums);
for (int i = 0; i < nums.length - 2; i++) {
    // Now two pointers will work
}
```

### Mistake 2: Not Skipping Duplicates for First Element
```java
// ❌ WRONG: Process all elements
for (int i = 0; i < nums.length - 2; i++) {
    // Will create duplicate triplets if nums[i] == nums[i-1]
}

// ✅ CORRECT: Skip duplicate first elements
for (int i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] == nums[i - 1]) {
        continue; // Skip if same as previous
    }
}
```

### Mistake 3: Wrong Duplicate Skipping Logic
```java
// ❌ WRONG: Checking wrong condition
if (i > 0 && nums[i] == nums[i + 1]) {
    continue; // This skips if NEXT is same (wrong!)
}

// ✅ CORRECT: Check PREVIOUS element
if (i > 0 && nums[i] == nums[i - 1]) {
    continue; // Skip if PREVIOUS is same
}
```

### Mistake 4: Not Skipping Duplicates After Finding Triplet
```java
// ❌ WRONG: Not skipping inner duplicates
if (sum == target) {
    result.add(Arrays.asList(nums[i], nums[left], nums[right]));
    left++;
    right--;
    // Will create duplicate triplets!
}

// ✅ CORRECT: Skip all duplicates
if (sum == target) {
    result.add(Arrays.asList(nums[i], nums[left], nums[right]));
    
    // Skip left duplicates
    while (left < right && nums[left] == nums[left + 1]) {
        left++;
    }
    // Skip right duplicates
    while (left < right && nums[right] == nums[right - 1]) {
        right--;
    }
    
    left++;
    right--;
}
```

### Mistake 5: Wrong Loop Boundary
```java
// ❌ WRONG: Can go out of bounds
for (int i = 0; i < nums.length; i++) {
    int left = i + 1;
    int right = nums.length - 1;
    // If i = nums.length - 1, left >= right!
}

// ✅ CORRECT: Leave room for at least 2 more elements
for (int i = 0; i < nums.length - 2; i++) {
    // Ensures left < right always possible
}
```

### Mistake 6: Using Set Instead of Proper Duplicate Handling
```java
// ❌ INEFFICIENT: Using Set
Set<List<Integer>> result = new HashSet<>();
// Then add all triplets to set
// This works but is slower and uses more space

// ✅ EFFICIENT: Skip duplicates during iteration
List<List<Integer>> result = new ArrayList<>();
// Skip duplicates at each level (shown in optimal solution)
```

## Why Sorting is Essential

### Without Sorting:
```java
nums = [1, -1, 0, 2, -2]
// Two pointers won't work predictably
// Can't decide when to move left vs right
```

### With Sorting:
```java
nums = [-2, -1, 0, 1, 2]
// Now we know: moving left increases sum, moving right decreases sum
// Can use Two Sum II logic!
```

**Sorting Enables:**
1. ✅ Two pointers logic (predictable movement)
2. ✅ Easy duplicate skipping (adjacent duplicates)
3. ✅ Efficient pruning (stop early if nums[i] > 0)

## Complexity Analysis

### Time Complexity: O(n²)
- **Sorting**: O(n log n)
- **Outer loop**: O(n) iterations
- **Inner two pointers**: O(n) for each outer iteration
- **Total**: O(n log n) + O(n × n) = O(n²)
- Dominated by the nested loops

### Space Complexity: O(1) or O(n)
- **Excluding output**: O(1) - only use pointer variables
- **Including output**: O(n) - worst case all triplets
- **Sorting space**: O(log n) to O(n) depending on sort algorithm

### Comparison with Brute Force:

| Approach | Time | Space | Notes |
|----------|------|-------|-------|
| Brute Force | O(n³) | O(n) | Too slow, TLE |
| Sort + Two Pointers | O(n²) | O(1)* | ✅ Optimal |
| HashMap | O(n²) | O(n) | Same time, more space |

*Excluding output array

## Pattern Connection: 3Sum vs Two Sum II

### Two Sum II:
```java
// Find ONE pair that sums to target in sorted array
int left = 0, right = n - 1;
while (left < right) {
    if (nums[left] + nums[right] == target) return indices;
    else if (sum < target) left++;
    else right--;
}
```

### 3Sum:
```java
// Find ALL triplets that sum to 0
Arrays.sort(nums);
for (int i = 0; i < n - 2; i++) {
    // Fix first element
    // Run Two Sum II on remaining array with target = -nums[i]
    int left = i + 1, right = n - 1;
    while (left < right) {
        // Same two pointers logic as Two Sum II
        // But collect ALL solutions and skip duplicates
    }
}
```

**Connection**: 3Sum = Two Sum II repeated for each fixed element!

## Complete Solution with Comments

```java
import java.util.*;

class Solution {
    /**
     * Finds all unique triplets that sum to zero.
     * 
     * @param nums Input array of integers
     * @return List of all unique triplets summing to 0
     * 
     * Time Complexity: O(n²) - sorting + nested loops
     * Space Complexity: O(1) - excluding output
     */
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        
        // Edge case: need at least 3 elements
        if (nums == null || nums.length < 3) {
            return result;
        }
        
        // Sort array for two pointers approach
        Arrays.sort(nums);
        
        // Fix first element with outer loop
        for (int i = 0; i < nums.length - 2; i++) {
            // Early termination: if smallest number > 0, no triplet possible
            if (nums[i] > 0) {
                break;
            }
            
            // Skip duplicates for first element
            // Check i > 0 to avoid index out of bounds
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }
            
            // Two pointers for remaining array
            int left = i + 1;
            int right = nums.length - 1;
            int target = -nums[i]; // We need nums[left] + nums[right] = -nums[i]
            
            while (left < right) {
                int sum = nums[left] + nums[right];
                
                if (sum == target) {
                    // Found a valid triplet!
                    result.add(Arrays.asList(nums[i], nums[left], nums[right]));
                    
                    // Skip duplicates for left pointer
                    while (left < right && nums[left] == nums[left + 1]) {
                        left++;
                    }
                    
                    // Skip duplicates for right pointer
                    while (left < right && nums[right] == nums[right - 1]) {
                        right--;
                    }
                    
                    // Move both pointers
                    left++;
                    right--;
                    
                } else if (sum < target) {
                    left++;  // Need larger sum
                } else {
                    right--; // Need smaller sum
                }
            }
        }
        
        return result;
    }
}
```

## Key Takeaways

1. ✅ **3Sum = Fix one + Two Sum II** pattern
2. ✅ **Always sort first** for two pointers approach
3. ✅ **Skip duplicates at THREE levels**: first element, left pointer, right pointer
4. ✅ **Check i > 0** before comparing `nums[i] == nums[i - 1]`
5. ✅ **Skip duplicates AFTER finding solution**, not before
6. ✅ **Loop bound**: `i < nums.length - 2` to ensure space for two pointers
7. ✅ **Early termination**: Break if `nums[i] > 0` (all remaining positive)
8. ✅ **O(n²) is optimal** - can't do better than checking all pairs per element
9. ✅ **Two pointers > HashMap** for this problem (cleaner, less space)
10. ✅ **Pattern extends to 4Sum, kSum** with same nested approach
